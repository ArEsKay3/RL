Workspace: users/rkirby/workspaces/engine_loop_test (README.md is the runbook). nemo_rl/ = git worktree of
swe_dump/nemo_rl on branch rkirby/engine-loop-test (pushed to origin = ArEsKay3/RL); only change: /v1/completions
token-id route added to the vLLM worker HTTP app (561ccba2). Never edit swe_dump/nemo_rl or the MLM fork for this.

Hosting: scripts/hold_node.sbatch holds one 4-GPU GB300 node (partition batch, qos interactive, 4 h, reaper-exempt
comment; nodes came immediately). scripts/start_engine.sh <vllm|minf> runs driver/serve_engine.py with `srun --jobid
<hold> --overlap` in the rl-gym.63635108-zstd container with the launcher's overlay mounts (scripts/mounts.txt);
the driver mirrors the SC (load_config + parse_hydra_overrides, configure_generation_config, RayVirtualCluster
[4 GPUs], VllmGeneration / MegatronGeneration skip_weight_load=False) and writes results/<engine>-<job>.url +
.status.json. Both engines ready ~3 min after launch (image import included). One engine per node.

Gotchas: driver must set policy.megatron_cfg.train_iters (SC injects grpo.max_num_steps); vLLM load_format must be
forced to auto (configure_generation_config sets dummy); vLLM lives only in /opt/ray_venvs/...VllmAsyncGenerationWorker
and cannot be imported raw there (nemo_rl's NamespaceTool patch runs at worker start); MINF fork /v1/completions has
no `n` (client repeats the prompt list); MINF response carries generation_token_ids/generation_log_probs, vLLM
token_ids + logprobs.token_logprobs (client.py normalizes). HF->Megatron conversion cached at
HF_HOME/nemo_rl/model__..._step_18_hf. Gym sends temperature 1.0 top_p 1.0 (dataset responses_create_params).
