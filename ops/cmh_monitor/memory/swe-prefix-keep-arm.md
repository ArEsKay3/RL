2026-09-25, rkirby: "make a change so that MINF no longer invalidates the prefix cache at weight updates ... relaunch the same configuration as P'' but use nvshmem and don't invalidate the cache".

**Mechanism.** `Megatron-LM/megatron/core/inference/engines/dynamic_engine.py`: `self._weight_epoch` (init 0) is bumped in `resume()` (every refit = suspend/resume) and passed as `hash_salt=self._weight_epoch` in `add_request`, so prefix-cache block hashes from earlier weights never match. In the default `kv_cache_management_mode=persist` (what P/G/J ran, with `enable_prefix_caching=true`, `refit_backend=nvshmem`) `deallocate/reinitialize_inference_state_buffers` return immediately, so the salt is the ONLY invalidation. NeMo RL has no other reset on the MINF path (vLLM path has `reset_prefix_cache`).

**Knob.** `InferenceConfig.invalidate_prefix_cache_on_weight_update: bool = True` (Megatron `inference/config.py`), read in `DynamicInferenceEngine.__init__`, gates the bump in `resume()`; NeMo RL `megatron_worker.py` forwards `mcore_generation_config.get("invalidate_prefix_cache_on_weight_update", True)` into `InferenceConfig(...)`; TypedDict key added in `nemo_rl/models/generation/megatron/config.py`. Hydra: `+policy.generation.mcore_generation_config.invalidate_prefix_cache_on_weight_update=false` (new key, needs `+`).
